# T00.09 — Validation harness and consumer pinning guide

## Goal

Make the contracts self-verifying: a CI harness that lints and validates
every artifact in this repository, plus the written procedure each consumer
repo follows to pin a tag and validate against it.

## Context

ADR-KEM-001 closes Gate 0 only when "every consumer's CI validates against a
tagged release" — that requires both sides: this repo proves its artifacts
are well-formed; consumers prove they build against the tag. Tool choices
(OpenAPI linter, JSON Schema validator) are unpinned by any spec — choosing
and recording them is part of this task, not a blocker to it.

## Steps

- ☑ Select and pin the toolchain (OpenAPI linter + ruleset, JSON Schema
  validator, schema-compatibility checker); record versions in this repo
- ☑ CI: validate every schema, lint every OpenAPI document, cross-check
  referenced error codes/permissions exist in their catalogs
- ☑ Compatibility gate: fail on breaking change without a version bump per
  Master §0.4 change classes
- ☑ Write `CONSUMING.md`: how a consumer pins a tag, regenerates types, and
  wires contract validation into its own CI (per-language notes for PHP,
  TypeScript, Go, Ansible)

## Acceptance criteria

- Harness runs green on the full Gate 0 artifact set
- A deliberately broken schema fails CI (negative test recorded)
- `CONSUMING.md` reviewed against each consumer repo's Phase 0 needs

## Evidence

CI run links/output for the green run and the negative test.
