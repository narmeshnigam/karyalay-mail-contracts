# T00.07 — Observability contract (`observability/`)

## Goal

Publish the cross-repo telemetry vocabulary: correlation/trace propagation
fields, metric and log naming conventions, and the shared severity/status
terminology — so four independently built systems produce joinable signals.

## Context

Each repo spec defines rich repo-local telemetry (Repo 1 Appendix H metrics
and alerts, Repo 2 Appendix K, Repo 3 §66–§68, Repo 4 §85). What must be
shared is the connective tissue: correlation IDs that survive the outbox and
NATS hops, tenant labels, and naming rules. Only that belongs here.

## Steps

- ☑ Extract the Master Contract's correlation/telemetry requirements into
  `observability/telemetry-contract.md` + field schema
- ☑ Define the propagation rule set: HTTP header ↔ event envelope ↔ job
  context (aligned with T00.02 envelope fields)
- ☑ Fix metric/log naming conventions (prefixes per repo, tenant label
  rules, cardinality cautions) strictly from the Master Contract; repo-local
  detail stays in repo specs
- ☑ Reconcile the four repos' status terminology (Repo 2 Appendix U exists
  for this) and record any conflicts as ADRs

## Acceptance criteria

- A single correlation ID demonstrably survives the documented path:
  API request → outbox event → consumer job (walkthrough written)
- No repo-local metric catalogs duplicated here

## Evidence

Contract files pass harness validation; terminology reconciliation note.
