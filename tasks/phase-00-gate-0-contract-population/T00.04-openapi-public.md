# T00.04 — OpenAPI: public, admin and mailbox-user APIs (`openapi/`)

## Goal

(C.1–C.96) that Repo 1 serves and Repo 2 consumes.

## Context

Repo 1's Appendix C catalog is exhaustive by invariant — no undocumented
routes. Repo 2's Appendix E consumption matrix (C.24–C.96) is the client-side
cross-check. Error responses reference the T00.01 catalog; security schemes
reference the T00.03 claims contract — hence the blockers.

## Steps

- ☑ Choose document granularity (single spec vs per-family files with a
  shared components file) and record the choice in the openapi/ README
- ☑ Author paths/operations for all 18 public families (C.1–C.96), with
  request/response schemas at the fidelity Appendix C defines

  carries idempotency/ETag semantics where Repo 1 §34 requires them
- ☑ Cross-check against Repo 2 Appendix E consumption matrix (noting its
  C.92–C.95 gap is intentional non-consumption, not an omission)
- ☑ Validate with the chosen OpenAPI linter (tool pinned in T00.09)

## Acceptance criteria

- Operation count reconciles to 96; C-numbers map 1:1 to Appendix C
- Zero inline-invented error codes or auth scopes
- Lint passes with the harness ruleset
