# T00.12 — Tag `v0.1.0` and close Gate 0

## Goal

Cut the first immutable contract release and record the evidence that closes
Gate 0 — unblocking Phase 0 in all four consumer repositories.

## Context

Consumers pin tags, never branches. The tag is the single event the entire
programme's dependency graph hangs on. ADR-KEM-002/003 decisions (T00.10,
T00.11) are strongly preferred before tagging but are not structural
blockers to the tag itself — they gate specific downstream tasks, not the
contract artifacts.

## Steps

- ☑ Final harness run green on the complete artifact set
- ☑ Write the release inventory (every artifact + its source appendix) into
  the annotated tag message / release notes
- ☑ Tag `v0.1.0`; verify immutability convention is documented (a tag is
  never moved; fixes ship as `v0.1.1+` per Master §0.4)
- ☑ Each consumer repo pins the tag per `CONSUMING.md` and records a green
  validation run (four evidence entries)
- ☑ Update each consumer repo's Phase 0 blocker rows from
  "karyalay-mail-contracts v0.1.0 (Gate 0 tag)" to unblocked
- ☑ Record Gate 0 closure in the decision register

## Acceptance criteria

- Tag exists; four consumer validation runs recorded; register updated

## Evidence

Annotated tag, release inventory, four consumer CI records.

## Progress — 2026-08-18

**Done here.** Harness green (21 checks, 0 failures) and Redocly clean.
`v0.1.0` tagged and annotated with the release inventory. The immutability
convention is documented in `CONSUMING.md` and enforced by the
`tag-is-immutable` CI job, which rejects a lightweight tag.

**Not done, and not doable from this repository.** Four steps require the
consumer repositories:

- Each consumer pins the tag per `CONSUMING.md` and records a green validation
  run — four evidence entries.
- Each consumer's Phase 0 blocker rows change from
  "karyalay-mail-contracts v0.1.0 (Gate 0 tag)" to unblocked.
- The decision register records Gate 0 closure once those four runs exist.

This is the split ADR-KEM-001 always described and BUILD-ORDER §4 restates:
**the tag unblocks Wave 1; the gate closes during it.** This task stays
in-progress until the four consumer runs are recorded, and it is the only Gate 0
task that does.

## Gate 0 closure — 2026-08-24

ADR-KEM-001's extra condition is that **all four consumers' CI validates
against the tagged release**. All four were run on 2026-08-24 and all four
verify in **FULL** mode — the tag fetched and compared, so a moved tag is
caught, not merely a hand edit:

| Consumer | Command | Result |
| --- | --- | --- |
| `karyalay-mail` | `php tools/contracts/vendor.php --check` | `contracts pin OK [FULL]: 14 files byte-identical to v0.4.0 (ea4ce36)` |
| `karyalay-webmail` | `pnpm run contracts:verify` | `contracts pin OK [FULL]: 6 files byte-identical to v0.4.0 (ea4ce36)` + `generated client is current` |
| `karyalay-mail-ops` | CI run [32664033271](https://github.com/narmeshnigam/karyalay-mail-ops/actions/runs/32664033271) | `contract pin verified in FULL mode` against `v0.4.0` |
| `karyalay-mail-infra` | `node scripts/vendor-contracts.mjs --check` | `contracts pin OK [FULL]: 12 files byte-identical to v0.2.1 (a5c1135)` |

**Gate 0 is closed.**

### The reading this closure rests on, stated so it can be disagreed with

Repo 3 validates against **`v0.2.1`** while the other three are on **`v0.4.0`**.
Gate 0 asks whether each consumer's CI validates against *a tagged release* —
not whether all four sit on the same one. Every consumer pins an immutable tag
at or above `v0.1.0` and verifies it byte-for-byte in FULL mode, so the
condition ADR-KEM-001 states is met.

**The drift is real and is not resolved by this closure.** It is a separate
question with a separate answer owed: advancing a pin is a decision with
evidence, because a pin is immutability protection rather than a version
number. Repo 3 consumes 12 artifacts and the three tags between `v0.2.1` and
`v0.4.0` changed OpenAPI operations (C.108–C.115), so the advance is not a
formality. Recorded in `START-HERE.md` §6 item 1 and unexplained by any ADR —
which is itself the finding.

Reading Gate 0 as blocked on the drift would have been the other defensible
call. It is not the one taken, because Gate 0's purpose is to prove the
distribution mechanism works end to end for every consumer, and four FULL
verifications against immutable tags prove exactly that.

### The correction BUILD-ORDER still owes

BUILD-ORDER §4's Wave 1 note says Gate 0 "closed on validation, not on
distribution", because at the time no repository had a remote and every pin
resolved through a local `file://` path. Both halves have since been resolved:
the remotes exist, and `contracts/PIN.json` names an
`https://github.com/narmeshnigam/karyalay-mail-contracts.git` source. That note
should not be read as current.
