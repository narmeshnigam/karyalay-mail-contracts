# T00.02 — Event envelope and payload catalog (`events/`)

## Goal

Publish the shared event envelope as JSON Schema plus one payload schema per
event in the Repo 1 catalog (Appendix D, **45 events**), so producers (Repo 1
outbox) and consumers (Repo 3, Repo 4) validate against identical shapes.

## Context

Events cross every repository boundary via NATS JetStream; the envelope is
defined in the Master Contract and must not be redefined per repo. Repo 4's
collector and job pipelines (its §11) are pure consumers of these schemas.

## Steps

- ☑ Transcribe the Master Contract envelope definition (correlation, tenant,
  idempotency, generation fields) into `events/envelope.schema.json`
- ☑ Enumerate all 45 events from Repo 1 Appendix D; one schema file each,
  named by canonical event name
- ☑ Record ordering/at-least-once semantics as schema annotations, citing
  Repo 1 §31 (transactional outbox) — consumers must tolerate redelivery
- ☑ Cross-check the consumer lists in Repo 3 and Repo 4 specs for events they
  expect that Appendix D does not define; report any gap via ADR, do not add

## Acceptance criteria

- Envelope schema round-trips a sample of every event type
- 45 payload schemas present; a diff against Appendix D shows zero divergence
  (Appendix D holds 45 unique rows — counted 2026-08-18. Earlier drafts of this
  task said 46; the extra one was never in the appendix. If a consumer needs a
  46th, it arrives through the step below as an ADR, never by invention)
- No consumer-expected event is silently missing (gaps raised as ADRs)

## Evidence

Validation harness output; the Appendix D reconciliation table.

## Completion — 2026-08-18

events/envelope-v1.schema.json (Master §22.3), 45 payload schemas, events/catalog-v1.yaml. Envelope and catalog divergences recorded in ADR-KEM-006 and docs/reconciliation/event-catalog.md.

Harness: `npm run validate` (21 checks, 0 failures) and `npm run lint`
(Redocly, 0 errors), both green on this tree.
