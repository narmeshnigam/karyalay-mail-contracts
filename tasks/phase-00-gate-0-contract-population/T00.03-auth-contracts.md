# T00.03 — Claims, roles and permissions contracts (`auth/`)

## Goal

Publish the token-claims shape and the permission catalog so Repo 1 (issuer
of authorization decisions), Repo 2 (claims consumer) and Repo 4 (console
authz) share one vocabulary.

## Context

Repo 1 §18 defines the five-factor authorization model (permission + object
relation + state + entitlement + restriction); Appendix B is the permission
catalog. Repo 2's auth handling (its §7, Appendix R) consumes the claims
shape. Nothing here invents policy — it transcribes vocabulary.

## Steps

- ☑ Define `auth/claims.schema.json` from Repo 1 §17 (OIDC claims the
  platform relies on, including tenant scoping)
- ☑ Transcribe the Appendix B permission catalog to `auth/permissions.json`
  with role → permission mappings exactly as specified
- ☑ Record the break-glass semantics reference (Repo 1 §18.1) as an
  annotation, not a mechanism definition
- ☑ Cross-check Repo 4's console role needs (its §9) against the catalog;
  raise gaps via ADR

## Acceptance criteria

- Claims schema validates a sample token for each defined role
- Permission catalog diff against Appendix B shows zero divergence
- No repo-private permission names exist in any consumer spec that are
  absent here (gaps raised as ADRs, not silently added)

## Evidence

Validation harness output; Appendix B reconciliation note.
