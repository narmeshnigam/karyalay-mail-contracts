# T00.01 — Machine-readable error catalog (`errors/`)

## Goal

Convert the Repo 1 error catalog (Appendix E) into machine-readable form so
every repository maps errors identically and no consumer invents codes.

## Context

The error catalog is the smallest contract and nearly everything else
references it (OpenAPI responses, event payloads, webmail error UX per
Repo 2 Appendix G). It goes first. Source of truth: Repo 1
`../../../karyalay-mail/docs/spec/repository-spec-v1.0.md` Appendix E and §39.

## Steps

- ☑ Define the catalog schema (JSON Schema): code, HTTP status, retryability,
  user-facing category, description reference
- ☑ Transcribe every Appendix E entry; no additions, no omissions
- ☑ Preserve the §39.1 nuance: `SUBMISSION_STATUS_UNKNOWN` maps to HTTP 202
  (ambiguous send outcome is not a failure)
- ☑ Add a `CHANGELOG.md` entry stub for the catalog under Master §0.4 change
  classes

## Acceptance criteria

- Every Appendix E code appears exactly once; a diff against the appendix
  shows zero divergence
- Catalog validates against its own schema
- Retryability and HTTP mapping recorded for every code

## Evidence

Validation harness output (T00.09) plus the transcription diff, stored with
the Gate 0 closure records.

## Completion — 2026-08-18

errors/error-catalog-v1.yaml + schema + CHANGELOG; 80 codes, zero divergence from Appendix E. Divergence against the Master baseline recorded in ADR-KEM-005 and docs/reconciliation/error-catalog.md.

Harness: `npm run validate` (21 checks, 0 failures) and `npm run lint`
(Redocly, 0 errors), both green on this tree.
